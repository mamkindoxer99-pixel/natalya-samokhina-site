НАТАЛЬЯ САМОХИНА — сайт с облачной галереей и защищённой панелью

ВАЖНО
Я подготовил файлы сайта, код облачной галереи, SQL-правила доступа и инструкцию.
Я не могу сам создать аккаунты GitHub/Supabase или принять за тебя их условия. Для публикации тебе нужно выполнить настройку ниже и вставить два публичных значения Supabase в config.js.

ЧАСТЬ 1. СОЗДАЙ БЕСПЛАТНЫЙ BACKEND В SUPABASE
1. Открой https://supabase.com/ и создай аккаунт.
2. Создай Organization (если попросят) и новый Project. Выбери Free plan.
3. Сохрани пароль базы данных в надёжном месте. Для этого сайта он не понадобится.
4. Дождись, пока проект создастся.
5. Открой SQL Editor -> New query.
6. Открой файл supabase_setup.sql из этой папки, скопируй ВЕСЬ текст, вставь в SQL Editor и нажми Run.
7. Открой Authentication -> Users и создай пользователя администратора (Add user / Create new user). Укажи email и придумай отдельный надёжный пароль. Если есть переключатель подтверждения email, для собственного admin-пользователя можно подтвердить его при создании.
8. В Authentication -> Sign In / Providers проверь, что Email включён. Отключи публичную регистрацию (Allow new users to sign up / Enable signups — выключить), чтобы посетители не могли создавать аккаунты. Не удаляй созданного администратора.
9. Открой Project Settings -> API (или API Keys). Скопируй Project URL и anon/public key (в новых интерфейсах может называться Publishable key).
10. Открой config.js в Блокноте. Замени значения:
   ВСТАВЬТЕ_PROJECT_URL -> твой Project URL
   ВСТАВЬТЕ_ANON_PUBLIC_KEY -> твой anon/public или publishable key
   Сохрани файл.

БЕЗОПАСНОСТЬ
- В config.js разрешено использовать только anon/public (или publishable) key.
- НИКОГДА не вставляй service_role, secret key или пароль базы данных в сайт, HTML, GitHub или чат.
- SQL-политики разрешают публично читать медиа и контакты, но добавлять/удалять файлы и менять контакты может только вошедший пользователь.
- Отключи публичную регистрацию. Создай только свой аккаунт администратора.
- Не делись паролем администратора.

ЧАСТЬ 2. ПРОВЕРЬ ЛОКАЛЬНО
1. Дважды нажми index.html или запусти через VS Code + Live Server.
2. Нажми «Управление» внизу справа.
3. Войди с email и паролем, которые создал в Supabase.
4. Попробуй загрузить небольшое фото. Оно должно появиться в галерее.
5. Проверь сайт в другом браузере/окне: загруженное фото должно быть видно и там.

ЧАСТЬ 3. БЕСПЛАТНО ОПУБЛИКУЙ НА GITHUB PAGES
1. Открой https://github.com/ и создай аккаунт.
2. Нажми New repository. Название, например, natalya-samokhina. Выбери Public и Create repository.
3. Нажми Add file -> Upload files.
4. Перетащи СОДЕРЖИМОЕ этой папки (index.html, config.js, папку assets и остальные файлы). Важно: index.html должен лежать в корне репозитория, а не во вложенной папке.
5. Нажми Commit changes.
6. Открой Settings -> Pages.
7. В Build and deployment выбери Deploy from a branch.
8. Branch: main; Folder: /(root); нажми Save.
9. Подожди несколько минут. На этой же странице появится адрес сайта вида https://ТВОЙ-ЛОГИН.github.io/natalya-samokhina/.

КАК ПОЛЬЗОВАТЬСЯ
- Для изменения галереи открой опубликованный сайт, нажми «Управление», войди как администратор.
- Выбери фото или видео. После загрузки материалы автоматически появятся у посетителей.
- Чтобы удалить файл, нажми «Удалить» на его карточке (кнопка видна только администратору).
- Телефон и email укажи в панели управления и нажми «Сохранить контакты».

БЕСПЛАТНЫЕ ЛИМИТЫ
Текущий бесплатный Supabase Free включает 1 ГБ Storage и ограничение 50 МБ на один файл; при превышении лимитов понадобится удалить старые файлы или перейти на платный тариф. Бесплатные проекты могут приостанавливаться после недели бездействия. GitHub Pages — бесплатный статический хостинг для такого сайта. Перед активным использованием проверяй текущие лимиты в аккаунтах.

Если при настройке что-то не совпадает с экраном, пришли скриншот — скажу, куда нажимать дальше.
